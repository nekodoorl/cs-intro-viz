# 合并冲突处理记录

本文件记录项目开发过程中真实发生的一次合并冲突，以及解决过程。

---

## 一、基本信息

| 项目 | 内容 |
|---|---|
| 时间 | 2026-11-27 |
| 涉及分支 | `docs/revise`（本地修订分支）与 `main`（网页上直接修改） |
| 冲突文件 | `README.md` |
| 处理人 | 梁钊源 |
| 合并提交 | `dd5db36` |

---

## 二、起因

1. 我先把需求文档、README、界面草图通过 PR 合并进了 `main`；
2. 随后在 **GitHub 网页上直接编辑** README，把自己的学号从 `2026xxxx` 改成了真实学号 `2610250234`，这次修改直接提交到了 `main`；
3. 与此同时，本地基于**修改前**的 `main` 建了 `docs/revise` 分支，对 README 做了整体重写（精简措辞、修掉占位符）。

两边都修改了 README 里同一张表格的同一行，于是产生了冲突。

---

## 三、现象

推送分支后，PR 页面提示：

> **This branch has conflicts that must be resolved**
> `README.md`

![PR 冲突提示](docs/images/conflict.png)

---

## 四、解决过程

1. 本地切到 `docs/revise` 分支，把最新的 `main` 合并进来：

   ```bash
   git checkout docs/revise
   git merge origin/main
   ```

2. Git 报出冲突，README 里出现冲突标记：

   ```text
   <<<<<<< HEAD
   | 梁钊源（组长） | 2026xxxx | 需求文档、仓库管理、PR 审核、集成与演示 | @nekodoorl |
   =======
   | 梁钊源（组长） | 2610250234 | 需求文档主笔、仓库管理、PR 审核、集成与演示主讲 | @nekodoorl |
   >>>>>>> origin/main
   ```

3. 两人一起确认这一行应该保留什么：**格式用新版的精简写法，学号用网页上填的真实值**。

4. 删除 `<<<<<<<`、`=======`、`>>>>>>>` 三行标记，最终保留：

   ```text
   | 梁钊源（组长） | 2610250234 | 需求文档、仓库管理、PR 审核、集成与演示 | @nekodoorl |
   ```

5. 提交合并结果并推送：

   ```bash
   git add README.md
   git commit --no-edit
   git push
   ```

6. PR 页面的冲突提示消失，可以正常合并。

---

## 五、经验

- 改 README 这类多人共用的文件前，先 `git pull` 拿最新版本；
- 尽量不要在网页上直接改文件，容易和本地分支产生冲突；
- 冲突不是"谁错了"，而是两边改了同一处，**商量保留哪个**才是关键。
